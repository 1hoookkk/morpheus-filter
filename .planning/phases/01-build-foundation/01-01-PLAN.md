  <files>none modified (diagnostic only)</files>
  <action>
1. Check if pluginval is installed: `where pluginval` or check common locations
2. If not installed, download from https://github.com/Tracktion/pluginval/releases (Windows x64 binary)
3. Run pluginval with maximum strictness:
   ```
   pluginval --strictness-level 10 --validate "C:/Users/hooki/do-it/build/TRENCH_artefacts/Release/VST3/TRENCH.vst3" --output-dir "C:/Users/hooki/do-it/.planning/phases/01-build-foundation"
   ```
4. If pluginval is unavailable, note this and proceed to Task 2

Key things to look for in output:
- "Failed to load" messages (indicates constructor crash)
- "Exception" or "crash" mentions
- "createPluginFilter" errors
- Audio processing test failures

<task type="auto">
  <name>Task 2: Investigate Standalone build failure</name>
  <files>none modified (diagnostic only)</files>
  <action>
1. Explicitly build the Standalone target with verbose output:
   ```
   cd C:/Users/hooki/do-it
   cmake --build build --config Release --target TRENCH_Standalone --verbose 2>&1 | tee standalone_build.log
   ```
2. If that fails, list available CMake targets:
   ```
   cmake --build build --target help
   ```
3. Check if Standalone appears in the target list
4. Look for linker errors or missing dependencies in build output
5. Check CMakeLists.txt FORMATS line includes "Standalone"

Common issues:
- Target name might be different (TRENCH_Standalone vs Standalone)
- Linker errors specific to Standalone (missing JUCE modules)
- Build filtering excludes Standalone
